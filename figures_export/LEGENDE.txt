PROVENANCE DES RÉSULTATS
------------------------
Toutes les figures sont calculées à partir des artefacts déjà produits par
l'expérience. Aucune valeur n'est simulée, estimée ou recopiée d'une autre
source :

  models/llmsemrec__amazon_beauty.pt        modèle entraîné
  models/eval__*__<dataset>.npz             rangs et scores par utilisateur
  cache/amazon_beauty_qwen3_0.6b.npy        embeddings texte gelés (12 101 x 1024)
  cache/amazon_beauty_siglip2_base.npy      embeddings image gelés (12 099 x 768)
  data/amazon_beauty.pkl                    jeu de données prétraité
  results/*.json                             métriques agrégées

Scripts : code/make_figures.py (partie A), code/make_figures_supporting.py (partie B)

Format : PDF vectoriel, 1 page par figure, polices embarquées, texte
sélectionnable, agrandissement sans perte. Utilisable directement en
\includegraphics.


JEUX DE DONNÉES ET PROTOCOLE
----------------------------
Amazon Beauty (5-core, catégorie « Beauty » du corpus Amazon 2014)
  22 363 utilisateurs | 12 101 items | 198 502 interactions | densité 0,0734 %
  couverture image 99,98 % | couverture texte 100 % | longueur moyenne 8,88

MovieLens-1M (utilisé uniquement dans la partie A)
  6 040 utilisateurs | 3 416 items | 999 611 interactions | densité 4,8448 %
  pas d'images (module visuel automatiquement désactivé)

Protocole : 5-core itératif, tri chronologique, leave-two-out (1 validation,
1 test par utilisateur), classement sur le CATALOGUE COMPLET.

Repères Amazon Beauty : LLM-SEMRec entraîné Recall@10 = 0,0193 ;
hasard = 0,000083 ; Popularity = 0,0120.

Écarts de configuration par rapport au papier (à déclarer) : machine CPU
uniquement, d = 128 et dz = 64 (contre d = 256), L = 20 (contre L = 50) ;
Qwen3-Embedding-0.6B (au lieu de 4B) ; SigLIP2-base ; 1 graine par modèle
(le papier en demande 5).

figS1_gate_weights.pdf   (NON INCLUSE — résultat négatif)

Cette figure a été construite dans l'intention de documenter la fusion à porte
sensible à la fiabilité (section IV-F), mais elle ne soutient pas le papier.

Mesure : poids de porte effectivement appris (éq. 18) sur le modèle entraîné —
item ID 0,900 ; image 0,030 ; texte (LLM) 0,022 ; feedback 0,015 ; temps 0,033.

La porte place 90 % de son poids sur l'identifiant et environ 2-3 % sur chaque
modalité de contenu, sans aucune adaptation à la popularité de l'item. La
« fusion multimodale à porte sensible à la fiabilité » dégénère pratiquement en
un modèle d'identifiants. Cela fournit l'explication mécaniste du résultat
d'ablation selon lequel remplacer la porte par une concaténation simple améliore
la précision (+24 %).

Sa place est dans une section « limites » ou « analyse d'échec », pas comme
résultat de soutien. Le PDF reste disponible dans le dépôt du projet :
figures/figS1_gate_weights.pdf
